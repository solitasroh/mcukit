Executive Summary

이번 S1의 목표는 “정리하되 rkit 안전 정책은 보존”입니다

무엇을 줄였나

  • bkit upstream에서 제거된 dead/live context 계열 파일을 rkit에서도 정리
  • context-init.js의 silent no-op 초기화 블록 제거
  • lib/context/index.js는 삭제하지 않고 bkit과 같은 facade로 축소

무엇을 보존했나

  • rkit.config.json 기반 permission 정책
  • MCU/MPU 위험 명령 정책: dd, mkfs, flash erase, force push
  • rkit audit 경로와 rkitVersion schema
최종 판단: 핵심 코드 변경, 권한 정책, E2E assertion 보강은 정상 반영됐습니다.

Before / After

구조 변경은 “삭제 + facade 축소 + broken bridge 수정”으로 정리됩니다

Before

context hierarchy, memory store, context fork 모듈이 hook과 일부 runtime에 남아 있었고, import resolver에는 _common/core 미정의 위험이 있었습니다.

→

S1 적용

사용처를 먼저 정리하고 dead/live 파일을 삭제했습니다. 권한 정책은 core.getConfig('permissions') 병합으로 보존했습니다.

→

After

context facade는 5 live module 기반 11 export만 제공하고, import resolver/permission manager는 smoke test로 보호됩니다.

Slide 8
Architecture E2E Fix

이제 E2E가 “실행만 성공”이 아니라 gate 결과를 검증합니다

Before

  • gateResult.status 출력: 실제 필드가 아님
  • good case도 metric 누락으로 pass가 아니었음
  • assertion이 없어 항상 exit 0 가능

After

  • gateResult.verdict 확인
  • bad case: architectureCompliance=85는 non-pass 검증
  • good case: 모든 design metric 충족 후 pass 검증
실행 결과: bad case verdict는 retry, good case verdict는 pass.
